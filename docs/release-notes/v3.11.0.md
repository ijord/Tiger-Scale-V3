# v3.11.0 — TigerScale V3+

The first published release of ijord's community fork adds on-scale TigerTag
programming, support for original Bambu spool tags, and the Guition JC3248W535
display board. It builds on the TigerTag Project's TigerScale V3 firmware.

## Added

- **Assign blank tags from inventory.** Place a spool with two blank NTAG21x
  tags on the scale, choose an untagged inventory spool, and confirm once to
  program the pair. The picker has a wrapping horizontal list, separate colour
  and black/white bars, and a material filter. Clear filaments appear under
  black/white; selecting a material resets the colour filter.
- **Erase both tags and release their inventory association.** Erase requires
  two visible writable tags and is disabled when both are already blank.
- **Read supported original Bambu tags without rewriting them.** Import a spool
  into inventory with a deterministic identity and matching TigerData+ catalogue
  data when a match is available. Subsequent placements recognise the same spool.
- **JC3248W535 / JC3248W535C support.** The browser installer offers this board
  alongside the Waveshare -3.5B and -3.5. Each has its own firmware image; follow
  the [Guition wiring guide](https://github.com/ijord/Tiger-Scale-V3/blob/main/docs/JC3248W535.md) for that board.
- **Spool-type selection** when assigning blank tags or reading a spool whose
  container type is unknown. Separate left/right tag indicators show reader
  status, with one beep per successfully read tag.

## Fixed

- Normal TigerTag programming writes only the 80 data bytes on pages 0x04–0x17,
  preserving the signature area. Message truncation matches the official SDK's
  raw 28-byte limit. Explicit erase clears the full 144-byte record.
- Read/write recovery retries pages and verifies the pair. If positioning still
  prevents a write or erase, the scale guides the user to move the spool toward
  the failing reader and retry.
- Inventory recovery reconciles existing associations rather than silently
  creating replacements. Removal clears the previous spool display and pending
  on-screen interaction. Bambu creation releases its HTTPS connection before
  verification and retries transient save failures.
- Weight filtering settles quickly after placement/removal while smoothing small
  changes. Automatic zero correction is limited to small drift; large offsets
  require an explicit empty-platform zero instead of silently taring a spool.

## Changed

- Known-spool details appear before waiting for weight stability. Erase remains
  disabled while the normal workflow is busy. Successful programming returns to
  normal reading without an extra success dialog.
- The browser installer and firmware update checks use this fork's releases at
  `ijord/Tiger-Scale-V3`. The installer identifies the fork and checks the image
  hashes for all three supported boards.
- The README links to this fork's installer and displays the Onshape logo at
  400 pixels wide.

## Installing and updating

Use the [browser installer](https://ijord.github.io/Tiger-Scale-V3/) in desktop
Chrome or Edge and select the exact board. A fresh browser installation erases
saved settings, including Wi-Fi and calibration.

To update from source while preserving settings, use
`bash scripts/flash.sh --fs` with the environment for your board. Firmware and
the web UI filesystem are separate images; upload both for this first fork
release. Units still running upstream firmware must first install the fork over
USB before their update checks point to this release channel.

The current partition table has two OTA application slots. Devices with an older
single-slot table need a USB reflash of the partition table and filesystem;
an OTA update cannot change that layout. The release does not change the current
partition table.

## Validation and limits

Local checks cover all seven PlatformIO environments and the inventory, picker,
reader, weight-filter and zero-baseline regressions. Hardware testing during
development covered the JC3248 scale's erase/program/read workflow and repeated
Bambu imports. A successful build does not establish hardware compatibility for
every board or every Bambu filament. Tag alignment still affects RF reliability;
the guided retry remains necessary for weak coupling.
